## 一、原始需求

用户希望建设面向沿海居民的台风实况网站，包含台风名称、位置、移动方向、风力及分级预警；本次要求先写计划书，并建立仓库存放。

本次不包含网站编码、真实数据接口接入、线上部署、付费采购或对外通知。

## 三、关键决策记录

### D1｜首期受众范围

暂按中国大陆沿海居民规划，先做有限城市试点。原因是语言与预警颜色需求匹配这一使用场景，但用户未指定省市；地区选择属于待确认项，而非已经批准的范围。

### D2｜分级预警采用官方信号展示

不采用“距海岸多少公里”或“中心风力多少级”自动判定红橙黄蓝。引用官方信号和完整防御指南，网站仅做地区筛选与信息状态说明。依据见 S4、S6。

### D3｜全国公报与本地信号分开

两类信息不同，不能用全国预警颜色替换用户所在区县的有效信号。地区缺失或匹配不明时明确提示，而不猜测。

### D4｜不假设网页等于免费数据源

S3 提示需授权使用。商业权限、缓存期限、批量访问、再传播及存储等条件均未确认；本次只核验公开入口，未执行爬取接入。

### D5｜第一版不做站外推送

先保证信息正确、状态同步和页面可用。浏览器/短信等通知还涉及授权、渠道成本与送达失败处理，列为第二阶段选项。

### D6｜缺测与解除分开

抓取不到预警不等于无预警；超过同步阈值不等于官方解除。必须记录未知、故障、历史与有效状态，避免给居民错误安全信号。

### D7｜交付格式与仓库

使用 UTF-8 Markdown，方便在 Git 中查看差异与持续维护。本次按本地 Git 仓库交付，不推定用户要将计划公开到 GitHub；远程归属及可见性后续确定。

仓库根目录位于本任务 `outputs/coastal-typhoon-watch/`。遵循用户目录习惯，最终方案放 `总结性文档/`，调研及决策记录放 `过程文件/`；根目录仅保留说明与 Git 配置文件。

## 四、尚未验证的依赖

- 数据服务方是否提供所需授权、足够的频率与完整解除消息。
- 首期地区具体预警规则、行政区边界及局部预警表达方式。
- 地图服务、坐标处理、成本、配额及部署适用要求。
- 当地官方通知和关联灾害入口的稳定性。
- 6 周排期与 54—77 人日估算是否符合实际人员条件。
- 性能、可用性和同步延迟目标能否达到；这些指标尚未实测。
