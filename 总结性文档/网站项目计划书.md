# 海岸台风信息站｜网站项目计划书

版本：v1.0

编写日期：2026-08-31

阶段：立项与开发准备；不是已上线服务或当前台风实况通报。

## 一、项目概述

建设一个手机优先、无需登录即可使用的台风信息网站，帮助沿海居民快速看懂“台风叫什么、在哪里、往哪走、风多大”，并查询所在地区的官方分级预警与防御指引。

首期默认服务中国大陆沿海居民，建议先选择同一省份的 1—2 个沿海城市试点，验证地方规则和数据质量后再扩展。具体城市由项目负责人确定；港澳台及其他地区如需覆盖，单独接入当地官方体系，不直接套用大陆颜色规则。

项目的核心价值是把权威信息变得易读、及时、与居民所在地区相关。网站不提供自行生成的台风预测，不替代当地气象、应急等部门的通告，不承诺生命安全保障或预警必达。

### 1.1 首期成功标准

- 普通居民打开首页后，能够在一次阅读中找到四项核心信息、资料时间和来源。
- 选择区县后，能够分清本地预警、全国台风公报以及台风中心风力。
- 地图加载失败时，仍可看到文字实况、官方预警及来源入口。
- 任何断流、数据过期、未覆盖地区，都有明确提示，不呈现为“安全”。

## 二、目标用户与使用场景

| 用户 | 常见问题 | 网站应提供的帮助 |
| --- | --- | --- |
| 沿海普通家庭 | 台风离我多远，要做哪些准备？ | 本地预警、台风位置、官方防御指引 |
| 老年居民及家属 | 地图看不懂，重要信息在哪里？ | 大字文字摘要、显著时间标记、无需地图也可使用 |
| 通勤与户外工作人员 | 是否需要调整安排？ | 所在地区有效预警及当地官方通告入口，不自行宣布停工停课 |
| 渔业、港区相关居民 | 海上风险怎么样？ | 台风路径与海洋预警官方入口；不承担航海导航或出海许可判断 |
| 社区服务人员 | 如何让居民查看同一条消息？ | 可分享的预警详情链接，打开时重新获取最新状态 |

核心流程：选择所在区县 → 阅读本地预警 → 查看台风四项信息 → 阅读完整官方通知和防御指引。

## 三、产品范围与优先级

### 3.1 第一版必须完成（P0）

1. 活跃台风列表：支持多台风切换，不能只展示最近发布的一条快讯。
2. 台风摘要：名称、编号、位置、移动方向及速度、中心附近最大风力。
3. 路径地图与文字列表：历史实况、最新定位、官方预报点；点击点位可查看时间与强度。
4. 地区选择：手动选择省、市、区县；定位可选，拒绝定位不影响使用。
5. 官方预警：按地区展示等级、灾种、发布单位、发布时间、适用范围和当前状态。
6. 预警详情：完整官方正文、官方防御指南、原文入口与发布/更新/解除记录。
7. 数据可信度：每个模块显示资料时间、同步状态、来源和异常说明。
8. 弱网与无障碍基础：文字优先、地图按需加载、键盘可操作、颜色之外还有文字等级。
9. 内部运维页：数据源状态、同步错误、异常数据隔离、审计记录和下线开关。

### 3.2 第二阶段（P1）

- 关注多个城市；在用户明确同意后提供浏览器通知或其他合规订阅渠道。
- 接入有授权的本地风雨观测/预报、暴雨、风暴潮、海浪等独立灾种信息。
- 历史台风回放、路径对比、地区通告整合。
- 家庭防台准备清单和经过审核的科普页面。

### 3.3 首期不做

- 自建气象预报模型、自动推算登陆倒计时、自行生成红橙黄蓝预警。
- 用台风中心距离、风圈或单个风速值判断居民处“安全/危险”。
- 自动生成疏散路线、开放避难所清单、航海指引或停工停课结论。
- 评论区、灾情众包、广告推荐、强制注册及付费查看基础预警。

## 四、核心信息设计

| 居民问题 | 必需字段 | 展示要求 |
| --- | --- | --- |
| 台风叫什么 | 中文名、英文名、官方编号、强度类别 | 没有正式名称时明确标记未命名；编号与年份用于区分同名系统 |
| 在哪个位置 | 中心经纬度、定位时刻、官方参考位置 | 默认以自然语言说明位置，经纬度供展开查看 |
| 往哪走 | 官方移动方向、移动速度或速度范围、预报路径、预报起报时间 | 明确“预报”；移动速度用 km/h，不与风速混淆 |
| 风力多大 | 中心附近最大风力等级、风速及单位、强度类别 | 固定注明“台风中心附近”，不得标成“你所在地风力” |
| 与我有什么关系 | 所选区县、覆盖该地的官方预警、可选的中心距离 | 距离标注计算基准与定位时刻，说明不是风险等级 |

中央气象台的台风快讯可作为字段口径参考，包含命名、编号、位置、强度、最大风力、参考位置和移动结论等信息；实际可获取字段以正式数据协议为准。[中央气象台台风快讯](https://www.nmc.cn/publish/nwp/index.html)

补充约定：

- 距离如以区县参考点计算，写明“距所选地区参考点约 × 公里”，不能冒称距用户住宅的精确距离。
- 本地风力仅在接入本地观测或预报后展示，注明站点/区域、平均风或阵风及资料时刻。
- 实况用实线，预报用虚线，并提供文字图例；所有未来点位显示有效时间及预报来源。
- 仅展示官方提供的不确定性范围；不得画出没有来源的预测锥，也不能把锥外标为安全区。
- 当前路径图不混合不同起报批次的未来点；如提供历史批次对比，单独标明。
- 风圈半径如有授权数据，保留各象限差异；缺失不补成完整圆，风圈不等于全部灾害影响区。
- 缺失值显示“暂无数据”，不填零、不猜测；风速换算注明换算值并保留原始单位。

## 五、分级预警方案

### 5.1 定位：展示官方预警，不自行发布

官方预警与网站辅助说明必须分层：预警等级、区域、时间、正文和防御指南来自有权发布的官方机构；网站只负责规范展示、地区筛选和同步状态说明。

预警信号具有统一发布要求，传播时须保留发布单位、时间及完整内容；项目上线前需由适任人员复核适用规则和授权安排。[中国气象局《气象灾害预警信号发布与传播管理办法》](https://www.cma.gov.cn/gzk/202005/W020220628619402421665.pdf)

### 5.2 四色预警的参考解释

下表为国家办法附件的台风预警信号门槛摘要，仅用于产品理解，**不是网站触发规则，也不是中央气象台全国台风预警公报的自动判级公式**。共同前提是可能或已经受热带气旋影响，并涉及持续性条件；完整含义以原文及适用地方规则为准。

| 信号 | 时间窗口 | 沿海/陆地平均风力门槛 | 或阵风门槛 |
| --- | --- | --- | --- |
| 蓝色 | 24 小时内 | ≥6 级 | ≥8 级 |
| 黄色 | 24 小时内 | ≥8 级 | ≥10 级 |
| 橙色 | 12 小时内 | ≥10 级 | ≥12 级 |
| 红色 | 6 小时内 | ≥12 级 | ≥14 级 |

依据：[中国气象局办法附件](https://www.cma.gov.cn/gzk/202005/W020220628619402421665.pdf)。这些指标不是台风中心最大风力与颜色的一一映射。

地方规则需要独立配置。例如广东的台风信号包含白色级别，不能只用四个固定枚举覆盖所有地区。[广东省气象灾害预警信号发布规定](https://weather.sz.gov.cn/gkmlpt/content/5/5614/post_5614517.html)

实现原则：保留来源中的信号代码、颜色、地区规则版本和原始含义；遇到未知代码仍展示官方原文并告警运维，不擅自归到最低等级。

### 5.3 地区匹配与多条预警

- 本地预警按官方行政区编码或发布范围匹配，不按“离台风最近的城市”推断。
- 全省、全市及区县范围要正确包含下级地区；局部范围无法可靠匹配时标明范围待核实。
- 全国台风预警公报和地方台风预警信号分区呈现，不能互相替代。
- 多条有效预警并存时全部保留；同一灾种可优先展示较高等级，但不能丢掉其他区域或其他灾种的原文。
- 不用“最严重颜色”覆盖全部灾种；台风、暴雨、海浪、风暴潮各自独立。
- 未接入某地区写“该地区预警服务尚未覆盖”；只有接口健康且覆盖范围完整时，才可写“暂未查询到有效官方预警”，并注明查询时间。

### 5.4 预警生命周期

每条预警跟踪发布、更新、升级、降级、解除及官方明确的有效期结束。以官方标识和版本关联前后记录；旧消息乱序到达时不能覆盖新版本。

页面另有“同步异常/状态待核实”状态：

- 收到明确解除信息，展示“官方已解除”及解除时间。
- 官方提供有效期且已结束，标记“已过有效期”，不能写成“官方已解除”。
- 无解除消息又无明确有效期时，不因超时或列表为空推断解除；达到同步异常阈值后移出“已确认有效”状态，提示核实官方渠道。
- 过时预警只能作为清晰标记的历史记录，不继续冒充当前有效预警。
- 上游定义为完整快照时，只有按其协议验证完整性后才解释记录消失；否则按状态未知处理。

### 5.5 防御指引与通知

预警详情直接呈现来源机构的完整防御指南。网站另行编写的科普、准备清单要单独标注，经审核后使用，不替代或删改官方内容。

显著说明：台风短时减弱或风雨暂歇，不意味着可以立即外出；应持续查看当地官方通知。[北京市应急管理局台风预警信号说明](https://yjglj.beijing.gov.cn/art/2024/5/13/art_2746_244054.html)

首期采用站内提示；后续通知以官方预警事件触发，使用“预警 ID + 版本 + 订阅地区”去重。发送前复核有效性；解除通知同样同步；失败进入有限重试并显示状态。通知服务不承诺一定送达，网站不能作为唯一应急信息渠道。

## 六、页面与交互规划

### 6.1 首页：先本地预警，后台风详情

首屏顺序为：所选地区及切换入口 → 本地官方预警 → 台风名称/位置/移动/风力四项摘要 → 来源和资料时间。地图位于其后，避免低性能手机先下载地图才能看到重要信息。

多台风时提供明确的切换入口和完整列表；默认排序规则可按官方关注信息与最新资料时间确定，不能仅凭距离排除可能影响本地的系统。

### 6.2 台风详情页

包括路径地图、文字轨迹表、强度变化、官方预报结论、资料时刻及来源。过去时刻与未来预报分开；停编、消散等终止状态按源记录标注，旧台风仍可在历史页查阅。

### 6.3 本地预警页

展示适用地区、发布机构、信号原貌、完整正文、防御指南及更新历史。分享链接打开时查最新状态；历史版本明确标注，避免旧截图或旧链接被误认为实况。

### 6.4 可用性要求

- 手机与电脑均可用，重点验证 360px 宽度、200% 缩放及大字模式。
- 等级同时有颜色和文字，不能只靠红绿或地图颜色表达。
- 重要按钮触控区域目标不小于 44×44 CSS 像素；正文默认目标不小于 16px。
- 自动刷新不打断阅读、键盘焦点或屏幕阅读器；更新时间变化可被用户感知。
- 不强制账号、手机号或精确定位；常用地区首期保存在本机并可清除。

## 七、数据来源与接入计划

### 7.1 候选来源

| 数据产品 | 优先核验对象 | 开发前必须确认 |
| --- | --- | --- |
| 台风实况、历史轨迹、预报点 | 中央气象台及合法授权的数据服务 | 访问方式、授权、字段、批次、单位、更新周期、活跃台风清单完整性 |
| 地方官方预警 | 试点地区气象部门或其授权分发服务 | 行政区覆盖、原文、版本、解除消息、服务连续性 |
| 全国台风公报 | 中央气象台官方产品 | 与地方信号区分、发布时间、传播权限 |
| 地图与地区边界 | 具备适用授权的地图服务 | 地图使用范围、坐标基准、行政边界版本、费用与限额 |
| 海洋及关联灾害 | 相应主管部门的官方服务 | 独立灾种体系、地区范围与授权；未接入先给官方入口 |

公开网页仅是调研和人工核验入口，不等于免费 API 或允许批量抓取。中央气象台网页明确提示数据使用需授权，因此不能把未公开的网页接口直接作为生产数据源。[中央气象台预警查询页及网站声明提示](https://www.nmc.cn/f/alarm.html)

### 7.2 接入步骤与上线门槛

1. 与候选供应方核实展示、再传播、缓存、存储和商业使用权限。
2. 获取样例与接口说明，核对时间、单位、地区范围以及更新/解除协议。
3. 建立字段映射、异常处理和人工对照样本；至少回放一次完整台风过程。
4. 对齐服务限额、故障支持方式与更新周期，开展持续联调。
5. 经数据负责人验收后启用正式模式；授权未落实则只进行明确标记的内部演示，不对居民上线“实况预警服务”。

### 7.3 时间与新鲜度

每条记录分别保存观测/定位时间、发布时间、预报有效时间和系统抓取时间。内部时间带时区；面向首期用户显示北京时间 UTC+8。刷新网页的时间不能冒充气象资料时间。

抓取频率按产品协议配置，不作“所有台风每分钟更新”的承诺。初始设计：预警优先采用授权事件推送；只支持轮询时，在限额允许下以 1—5 分钟为联调起点。台风产品按上游更新安排检查，最终参数在接入验收后确定。

同步过期阈值按产品设置：优先使用上游承诺的下一次发布时间加宽限；否则采用已确认更新周期和连续失败次数。没有可靠周期时显示“更新周期待确认”，不凭感觉给出“实时正常”。

发生断流：显示最后一条可追溯资料及其历史属性 → 撤下未经确认的当前预警状态 → 显示故障说明与官方入口 → 告警值守人员 → 恢复后核对遗漏更新与解除事件。不能用旧数据填补成新的轨迹。

## 八、技术方案与数据模型

### 8.1 建议架构

采用“手机优先网页 + 只读查询服务 + 独立数据接入任务 + 数据库/缓存”的轻量架构。首期优先采用团队熟悉的技术，不在数据源未落实前锁定框架、地图厂商或付费服务。

处理流程：授权来源 → 接入及校验 → 标准化存储与版本记录 → 查询缓存 → 居民网页。监控覆盖每一段；异常记录进入隔离区，不直接显示给居民。

前端不持有供应方密钥，不直接请求未授权接口；后台定时任务不依赖某个居民打开页面才运行。台风路径、预警和地图采用可替换适配层，避免因单一供应商变更而重写页面。

### 8.2 最小数据模型

| 对象 | 主要字段与约束 |
| --- | --- |
| Typhoon | 稳定 ID、年份、官方编号、中文/英文名称、活动状态、来源 ID |
| Observation | 台风 ID、定位时间、经纬度、最大风速/风力、强度、移动信息、发布时间、抓取时间、来源版本 |
| ForecastPoint | 台风 ID、发布机构、起报时间、有效时间、经纬度、预报强度；不同起报批次不得混连 |
| Warning | 原始 ID、版本、关联前序 ID、灾种、地区规则、原始等级、发布机构、适用范围、正文、发布时间、有效期、解除信息 |
| Region | 行政区编码、层级、边界版本、可选参考点和坐标基准 |
| SourceHealth | 产品 ID、最近成功同步、最近资料时间、周期、失败次数、新鲜度状态、覆盖状态 |

预警不能强制关联单个台风，可能涉及多个系统或源数据没有提供关联。风速单位与平均时段如由来源提供，必须保留；不同机构口径不混合计算。原始报文仅在授权允许的期限和范围内留存，避免将原始数据提交到 Git。

### 8.3 工程与安全要求

- 发布关键数据前校验字段、单位、时间顺序、坐标范围和重复版本；可疑数据隔离后人工核查。
- 坐标转换使用明确的地图服务规范，测试海岸线及参考城市位置，防止地图整体偏移。
- 预警正文按安全文本/受控格式呈现，防止上游 HTML 导致脚本注入。
- 后台限权、记录操作日志；密钥仅放受控环境，不进代码仓库；对外接口限流。
- 关注地区优先本地保存；定位只在明确同意后使用，精确坐标不进入默认访问日志。
- 备份、回滚和降级入口需演练；发布前确认地图、数据、内容传播、隐私及部署相关要求。

## 九、实施安排与人员投入

建议以数据授权及测试接口到位作为开发排期起点。以下为 6 周内部规划假设，不是承诺工期；授权、采购和审核等待时间另计。

| 阶段 | 时间 | 主要交付物 | 放行条件 |
| --- | --- | --- | --- |
| 接入准备 | 开工前，周期待定 | 授权确认、试点地区、样例数据、地方规则记录 | 可合法获取必需数据与解除事件 |
| 产品与数据设计 | 第 1 周 | 页面结构、字段字典、异常状态、预警生命周期设计 | 产品与数据负责人共同确认 |
| 数据底座 | 第 2 周 | 接入任务、存储、版本处理、健康监控 | 样例与原文对照通过 |
| 核心页面 | 第 3 周 | 地区选择、台风四项摘要、文字路径、预警详情 | 手机端基本流程完整 |
| 地图与联调 | 第 4 周 | 实况/预报地图、多台风、故障降级、后台查询 | 地图与文字一致，错误状态可验证 |
| 安全与回放测试 | 第 5 周 | 历史过程回放、预警生命周期测试、性能与无障碍检查 | 严重问题清零，预警不误解除 |

角色建议：1 名产品/项目负责人、1 名前端开发、1 名后端/数据开发，配合兼职测试/设计及具备气象业务知识的审核人员。小团队可兼任，但预警口径与上线审批应有独立复核。

工作量粗估：产品与内容 8—12 人日、前端 18—25 人日、后端与接入 18—25 人日、测试与发布 10—15 人日，合计 54—77 人日。估算基于一个主要数据源、有限试点地区和站内提示，不包含复杂推送或全国多规则适配。

## 十、预算编制与运营

本阶段不虚报数据价格或供应商报价。预算分为：

- 一次性建设：人日 × 团队实际单价 + 内容/规则审核 + 必要采购。
- 持续费用：数据授权 + 地图配额 + 服务器/数据库/流量 + 域名 + 监控备份 + 值守维护。
- 第二阶段费用：消息发送、账号与订阅管理、更多灾种与地区接入。

在已核实费用基础上另留约 20% 项目预备金，作为内部规划假设，最终由负责人批准。每个供应项至少登记授权范围、计费单位、限额、超额成本及故障支持方式。

运营重点为台风活跃期间的数据连续性和预警更新。正式开放前必须明确值守负责人及替补、故障通知渠道、临时下线权限和恢复复核流程；没有值守保障时不得宣传为可靠的应急通知服务。

## 十一、验收标准

以下指标是待实现的验收目标，不代表本仓库已实现这些能力。

| 验收项 | 测试方法与通过标准 |
| --- | --- |
| 四项核心信息 | 固定样本中名称/编号、位置、移动、风力及单位与来源 100% 一致；无值时明确缺失 |
| 资料时间 | 所有核心模块显示资料时间及来源；抓取时间不冒充观测时间 |
| 实况与预报 | 过去和未来视觉/文字均可区分；地图与轨迹表一致；不同起报批次不混连 |
| 地区覆盖 | 测试省/市/县包含、局部区域、边界与未覆盖地区；不得将全国公报当成本地信号 |
| 预警生命周期 | 发布、升级、降级、重复、乱序、解除、过期、断流等用例全部通过；无静默解除 |
| 同步延迟 | 从系统成功接收一条更新到前端可见，目标 P95 ≤60 秒；另测源发布时间至接收延迟并单独报告 |
| 数据异常 | 缺测、超时、非法坐标、错误单位、旧批次等被识别；不得自动变为无风险 |
| 页面性能 | 约定 4G 模拟条件与中档手机下，首屏核心文字目标 3 秒内可见；地图失败不阻塞 |
| 可用性 | 邀请至少 8 名目标居民（含较低数字熟练度者），至少 7 人能在 30 秒内找到四项信息和本地预警；无人误认中心风力为本地风力 |
| 无障碍 | 360px 宽屏、200% 缩放、键盘访问、大字模式和无颜色辨识情况下完成核心查询 |
| 负载与可靠性 | 首轮以 100 次/秒缓存读请求为压测假设，记录配置、错误率和延迟；后按实际流量扩容；月可用性内部目标 99.9% |
| 安全与运维 | 无密钥入库；正文注入防护、恢复演练、降级入口、故障通知及值守责任通过检查 |

上线红线：未取得必要授权、不能跟踪预警解除、误用地方规则、数据时间混淆、缺失被当作安全、核心路径存在严重可用性问题，任一存在均不对居民正式上线。

## 十二、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 授权或接口不可得 | 无法提供可靠实况 | 授权前置；维持内部演示，不用未经许可抓取替代 |
| 上游断流/解除丢失 | 居民看到过期状态 | 版本追踪、数据健康提示、独立官方入口、人工复核 |
| 把中心风力当本地风力 | 错误理解个人风险 | 永久标注测量位置；本地风力单独建模；居民测试 |
| 地方规则差异 | 预警误读 | 按地区保留原始级别，逐地区复核；不统一反推颜色 |
| 只展示风和路径 | 忽略降雨与海洋灾害 | 首页提示能力范围，提供相关官方入口，后续独立接入 |
| 灾害期间访问激增 | 关键信息不可达 | 缓存、文字降级、限流、负载演练和扩容预案 |
| 通知未达或旧消息转发 | 错过或误读状态 | 首期站内提示；分享页查新状态；不承诺必达 |
